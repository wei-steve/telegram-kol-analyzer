# 币种级固定入场阈值设计

## 目标

把范围入场当前使用的统一百分比阈值改为按币种配置的固定价格差，避免 BTC、ETH 等币种在不同绝对价格下产生差异过大的阈值。

每个允许自动交易的币种拥有四项设置：

- 最大亏损 USDT；
- 第一腿市价阈值；
- 第一腿限价偏移；
- 第二腿限价偏移。

初始配置为：

| 币种 | 最大亏损 USDT | 第一腿市价阈值 | 第一腿限价偏移 | 第二腿限价偏移 |
| --- | ---: | ---: | ---: | ---: |
| BTC | 20 | 200 | 90 | 90 |
| ETH | 15 | 4 | 2 | 2 |

SOL、其他现有币种以及以后新增的币种，三项固定入场阈值默认均为 `0`。

## 配置模型

在全局交易设置中增加一个按标准化币种代码索引的配置对象。每个币种保存：

- `market_leg_threshold`：第一腿允许转换为市价单的最大固定距离；
- `first_limit_offset`：第一腿使用限价单时相对范围近端的固定偏移；
- `second_limit_offset`：第二腿相对范围远端的固定偏移。

配置接受数字或十进制字符串，拒绝负数、非有限数和非法格式。持久化时使用规范化十进制字符串，计算时从字符串构造 `Decimal`，避免小价格币种的阈值被二进制浮点误差吞掉。最终委托价格仍通过现有合约规格按 Deepcoin 价格步长规范化。

新勾选的币种立即在前端配置状态中获得 `0 / 0 / 0`。后端也对缺失币种返回相同的安全默认值，避免旧页面、旧请求或缺失字段绕过默认语义。

旧的统一百分比字段暂时保留在持久化模型和接口兼容层中，便于回滚，但新的范围入场决策和价格计算不再读取它。现有“单点附近市价容忍 %”保持不变，因为单点信号不产生范围分腿。

## 下单规则

只有真实范围入场使用三项固定阈值。明确写出“市价”“现价”“立即入场”等含义的策略，继续生成一条承担 100% 风险预算的市价腿。

### 多单

范围标准化为 `low <= high`：

1. 第一腿的市价判断锚点为 `high`。
2. 当 `market_leg_threshold > 0` 且 `abs(current_price - high) <= market_leg_threshold` 时：
   - 第一腿以当前市价提交，占 50% 风险预算；
   - 第二腿限价为 `low + second_limit_offset`，占 50% 风险预算。
3. 否则：
   - 第一腿限价为 `high + first_limit_offset`；
   - 第二腿限价为 `low + second_limit_offset`；
   - 两腿各占 50% 风险预算。

### 空单

范围标准化为 `low <= high`：

1. 第一腿的市价判断锚点为 `low`。
2. 当 `market_leg_threshold > 0` 且 `abs(current_price - low) <= market_leg_threshold` 时：
   - 第一腿以当前市价提交，占 50% 风险预算；
   - 第二腿限价为 `high - second_limit_offset`，占 50% 风险预算。
3. 否则：
   - 第一腿限价为 `low - first_limit_offset`；
   - 第二腿限价为 `high - second_limit_offset`；
   - 两腿各占 50% 风险预算。

### 零值

- `market_leg_threshold = 0` 明确表示禁用第一腿市价转换，而不是等待当前价与锚点完全相等。
- 任一限价偏移为 `0` 时，对应限价腿直接使用原始范围端点。
- 如果交易所价格步长规范化后两条限价腿经济上完全相同，继续使用现有等价腿合并机制，生成一条承担合并后风险预算的腿。

## 页面设计

交易设置页在允许交易币种选择器下方，为每个已选币种显示一行或一个响应式卡片，包含：

- 币种；
- 最大亏损 USDT；
- 第一腿市价阈值；
- 第一腿限价偏移；
- 第二腿限价偏移。

字段使用 `min="0"`，并允许足够细的小数输入，例如 `0.000001`。标签使用“固定价差”或“固定阈值”，避免与百分比混淆。

现有“现价入场最大偏离 %”从页面移除。现有“单点附近市价容忍 %”保留，并明确标注仅适用于单点“附近”类信号。现有区间入场方式字段在兼容层保留，但固定端点规则生效后不再影响新范围订单；页面不再把它呈现为有效的范围定价控制。

保存请求同时提交允许币种、币种最大亏损和币种固定阈值。取消选择币种时可以保留其已保存配置，以便以后重新选择时恢复；首次出现且没有历史配置的币种才使用零值。

## 兼容与发布

加载不包含新字段的旧设置时：

- BTC 使用 `200 / 90 / 90`；
- ETH 使用 `4 / 2 / 2`；
- 其他币种使用 `0 / 0 / 0`。

保存一次设置后，新字段进入服务器本地数据库。旧百分比配置继续保留但不参与范围下单。回滚旧版本时，旧版本仍可读取原百分比字段。

该变更只影响更新之后创建的新入场订单，不修改已经提交的市价单、限价单、条件单或现有持仓。

## 验证

自动化测试覆盖：

- BTC、ETH 初始迁移值；
- 新币种三项阈值默认零；
- 配置 API 的保存、读取、非法负值和高精度小数；
- 页面每币种四项字段的显示、编辑和新增币种初始化；
- 多单和空单在市价阈值以内、以外以及阈值为零时的分腿；
- 第一腿和第二腿使用各自独立的限价偏移；
- `0.000001` 等小数经过十进制计算和交易所 tick 规范化后的结果；
- 明确市价信号和单点附近信号不发生回归；
- 等价腿合并、风险预算分配和现有提交边界不发生回归。

本地完成单元测试和页面静态测试后，按照项目流程提交并推送到 `codex/deepcoin-auto-trading-v1`。真实配置保存、交易所合约规格和服务运行状态只在服务器验证；验证不得创建真实测试持仓。
