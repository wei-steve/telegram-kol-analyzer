# 持仓首屏即时快照设计

## 背景

生产实测表明，直接打开 `/?view=positions` 时首屏持仓可见需要约
7.1 秒。服务端 `/positions-panel?initial=positions` 的冷请求约
6.5 秒，而紧随其后的请求约 0.29 秒；浏览器重载还包含约 1.8 秒的
页面壳加载。当前响应体只有约 12 KB，因此主要瓶颈不是 HTML 体积，
而是首次 Deepcoin 实时仓位及 TPSL 查询处于首屏关键路径。

## 目标

- 最近已有成功快照时，持仓首屏不等待 Deepcoin，服务端目标低于
  300 ms，浏览器可见目标低于 1 秒。
- 后台刷新完成后，页面自动追上新的实时持仓。
- 服务重启后仍可读取最近一次成功快照。
- 快照只用于展示；平仓、止盈止损及其他交易动作继续走实时校验，
  不得读取展示缓存作为写入依据。
- Deepcoin 失败时保留最近成功快照并明确显示陈旧/失败状态。

## 方案比较

### 方案 A：只复用长期 HTTP 连接

长期共享只读 `httpx.Client`，减少 DNS、TCP 和 TLS 冷启动。改动较小，
但无法消除 Deepcoin 偶发 6–8 秒延迟，仍会让上游网络阻塞首屏。

### 方案 B：持久化成功快照并后台刷新（采用）

首屏读取最近成功的 Deepcoin 展示快照，本地数据库中的策略归属每次
仍即时重新计算。返回响应后以单航班方式后台刷新 Deepcoin；浏览器在
快照陈旧或刷新中时短暂轮询，拿到新版本后无干扰更新。

该方案直接移除首屏对 Deepcoin 的同步依赖，也能覆盖上游超时、服务
重启和网络波动。代价是页面可能先显示数秒前的数据，因此必须显示
快照时间和状态。

### 方案 C：只缓存完整 HTML

可以最快返回，但会缓存本地策略归属、操作按钮和链接状态，容易让已经
变化的本地执行证据滞后。故不采用。

## 架构

新增线程安全的 `LivePositionSnapshotStore`：

- 仅保存 `_load_exchange_live_snapshot` 的成功结果、捕获时间、版本和
  最近刷新错误；
- 使用进程内内存作为热路径；
- 使用数据库同目录下的原子 JSON 文件跨重启持久化；
- JSON 编解码显式支持 `datetime`，不使用 pickle；
- 通过锁实现 `begin_refresh`/`finish_success`/`finish_failure` 单航班，
  同一时刻最多一个展示刷新读取 Deepcoin。

`/positions-panel?initial=positions` 的数据流：

1. 即时读取本地 pending/holding 策略记录。
2. 从 snapshot store 读取最近成功的 Deepcoin 快照。
3. 若有快照，立即用最新本地策略证据重新做 attribution 并渲染。
4. 若快照超过刷新间隔，响应返回后启动后台刷新。
5. 若完全没有快照，保留现有同步加载作为首次兜底；部署验证会主动预热，
   使真实用户不承担这次冷加载。
6. Deepcoin 刷新失败不覆盖成功快照，只更新错误状态。

完整旧版 `/positions-panel` 和三个历史分页继续保持现有行为；交易写入
端点和管理执行器不接入 snapshot store。

## 页面状态

持仓根节点增加：

- `data-position-snapshot-version`
- `data-position-snapshot-state`
- `data-position-snapshot-captured-at`

页面显示“刚刚更新 / N 秒前更新 / 正在刷新 / 刷新失败，展示最近成功
数据”。超过 30 秒视为陈旧，但仍显示持仓卡片，避免白屏。

前端在初始快照为 `refreshing`、`stale` 或 `error` 时，以有界退避
（1 秒、2 秒、4 秒、最多三次）重新获取首屏片段。只在版本变化时替换，
并复用现有非干扰刷新逻辑。

## 生命周期与错误处理

- 应用启动时若存在持久化快照则直接加载到内存。
- 应用启动后后台预热一次，不阻塞服务启动。
- 写文件使用同目录临时文件加 `Path.replace()`，避免半写文件。
- 文件损坏时记录错误并按“无快照”处理，不影响服务启动。
- Deepcoin 返回空仓位属于有效成功快照；只有显式 `error` 才不覆盖。
- 后台任务异常必须释放单航班标记，允许后续请求重试。
- 快照包含页面本来可见的交易所信息，仍保存在现有受控 `data` 目录，
  不写日志、不提交 Git。

## 静态资源

当前 CSS/JS URL 已带进程级版本参数。为减少重复重载成本，静态响应在带
正确版本参数时使用长期 immutable 缓存；新部署因版本变化自动换 URL。
该优化不改变数据缓存策略。

## 验证

- 单元测试覆盖 JSON 往返、原子持久化、损坏文件、单航班和失败保留。
- Web 测试覆盖缓存命中不调用 Deepcoin、陈旧快照触发后台刷新、无快照
  同步兜底、空仓成功覆盖、快照状态 DOM 属性和前端有界追新。
- 保留现有持仓归属、标签页懒加载、交易写入及 Deepcoin 客户端回归。
- 生产先做只读安全窗口检查，再部署并主动预热；验证部署 SHA、服务状态、
  首屏体积、三次全新 `?view=positions` 可见耗时以及无交易写入。
