# DeepCoin 历史仓位页面设计

## 目标

仅重做交易执行台的“历史仓位”页签，使其以 DeepCoin USDT 合约 App 的历史仓位页面作为视觉和信息层级参考；保留真实仓位数据和现有其他三个页签的行为。

## 范围

- 仅影响“交易持仓”中的“历史仓位”页签。
- 保留现有数据获取、策略归属及四页签框架。
- 不改变当前持仓、当前委托、历史委托的视觉样式。
- 默认使用未分组的真实列表；现有按群组视图不作为此页的主要呈现。

## 布局与信息层级

历史仓位页在激活时使用 DeepCoin 风格的白色内容画布和紧凑列表分隔。页签激活态使用官方式橙色下划线。

每条历史仓位按以下顺序显示：

1. 合约代码、方向（多/空）和离场原因。
2. 账户、保证金模式和杠杆信息（数据可用时）。
3. 三列主指标：开仓均价、已实现盈亏、最大持仓量。
4. 三列补充指标：平仓均价、已平仓量；缺失指标保持布局稳定。
5. 开仓时间与最后平仓时间，标签在左、值右对齐。
6. 策略归属作为低权重辅助标签，不抢占 DeepCoin 的主交易数据层级。

数值使用真实交易数据。没有已实现盈亏、账户、模式或杠杆等交易所字段时，保持字段省略或使用项目已有的安全兜底文本，不伪造数据。

## 排序契约

历史仓位始终按以下稳定键排序：

1. `exited_at`（最后平仓时间）降序。
2. `entered_at`（开仓时间）降序，作为缺失最后平仓时间的回退。
3. 稳定记录标识降序，消除同一时间的非确定性顺序。

缺少最后平仓时间的记录排在有最后平仓时间记录之后，并保留开仓时间用于显示。列表视图和群组生成前均使用相同的已排序数据，确保同步与刷新不会改变顺序。

## 交互与兼容性

- 四个页签继续可切换，活动页签状态和可访问性属性保持正确。
- 历史仓位选择后显示新的 DeepCoin 布局；窄屏优先，宽屏在居中的阅读列内呈现，避免桌面卡片被拉得过宽。
- 不新增下单、平仓或外部 API 写操作。
- 数据不可用与空列表继续沿用现有明确提示。

## 验收

- 历史仓位默认从最新最后平仓时间开始展示，时间缺失和并列时间也稳定可预测。
- 页面视觉具备截图中的白底、橙色激活标识、无圆角大卡片、交易数据分栏与时间右对齐。
- 所有显示数值来自既有数据模型；不输出敏感字段。
- 其他三个页签和现有路由、刷新机制不回归。
