## 1. 用户看到的问题

左侧导航「策略」页，标题「实盘观察台 · 策略记录」。用户原话：

> 这个页面不知道作用是什么，写着待处理，我也不知道需要做什么处理，而且日期都很久远的。

截图（群组选「大漂亮社区 11分组」）：待处理 7、全部 42、执行中 0、待入场 0、已结束 42；
待处理里 6 张是 07-21/07-22 的旧卡片、1 张 09-29；卡片标签是英文状态码
（`策略 expired`、`执行 not_started`、`归属 unbound`）；每张卡的标签行被下一张卡盖住。

### 2.2 「待处理」的判定：**只看有没有异常标记，不看这条策略是不是早结束了**

一条策略只要命中下列任一条，就永远算「待处理」：

| 代码 | 页面文字 | 级别 | 是否检查策略已结束 |
|---|---|---|---|
| `recognition_failed` | AI识别失败 | 严重 | **否** |
| `recognition_evidence_missing` | AI权威识别证据缺失 | 严重 | **否** |
| `recognition_disagreement` | AI识别存在关键分歧 | 复核 | **否** |
| `entered_without_binding` | 策略已入场但没有唯一真实仓位 | 严重 | 只看 `entered`，**不看群是否自动交易** |
| `missing_stop` | 真实持仓缺少止损 | 严重 | 要求在场仓位 ✔ |
| `execution_failed` | 交易执行失败 | 严重 | **否** |
| `management_unconfirmed` / `management_blocked` | 仓位管理尚未确认交易所结果 | 警告 | **否** |
| `take_profit_convergence_unknown` / `_conflicted` | 止盈收敛… | 严重/警告 | **否** |
| 交易所侧（`unattributed_position` 等） | 交易所仓位未归属策略 等 | 严重/警告 | 基于实时快照 ✔ |

没有任何时间窗、没有「已知悉」机制，也没有「策略已结束就不用管了」的规则。

### 2.3 生产数据：**当前全部 203 条「待处理」没有一条是用户能做点什么的**

生产库只读点查（1370 条策略记录，全表小，按主键/索引逐条补查）：

| 构成 | 条数 | 说明 |
|---|---|---|
| 已过期（expired）+ AI识别失败 | 124 | 全是 2026-06 的老记录，`parse_source=text/text_ai`，那时还是旧识别管线 |
| 已离场（exited）+ AI识别失败 | 44 | 同上 |
| 已作废（invalidated）+ AI识别失败 | 1 | 同上 |
| 已入场（entered）+ 「策略已入场但没有唯一真实仓位」 | 28 | **28 条全部来自只通知不交易（`notify_only`）的群**，这些群本来就不会下单，永远不会有仓位；页面却标成「严重」 |
| 已离场 + 止盈收敛冲突 | 6 | 仓位早已平掉，冲突无从处理 |

「大漂亮社区 11分组」的 7 条逐条核对：6 条是 06-17/06-18 喊单、AI 识别失败、
早已过期或离场（#1359、#1360、#1372、#1373、#1390、#1395）；1 条是 09-07 的 #1552，
已离场，挂着「止盈收敛冲突」。卡片上显示 07-21/07-22，是因为卡片时间取的是
「所有相关行里最晚的 updated_at」，那批 AI 识别行在 7 月被回填改写过——
所以连「日期」都不是喊单时间，更让人看不懂。

### 2.4 计数口径

- 「全部 / 执行中 / 待入场 / 已结束」按策略状态分桶：全部 = 执行中 + 待入场 + 已结束（+ 少量其他状态）。
- 「待处理」是**另一个维度**（有没有异常），和状态桶交叉，不是其中一桶。
  所以「全部 42 = 已结束 42」同时「待处理 7」在数学上不矛盾——那 7 条就是已结束里的 7 条。
  但它和状态桶并排放成同一排按钮，看起来就像五选一的分区，于是读成矛盾。
- 额外缺陷：Deepcoin 快照读取失败时，计数会把**所有**能挂交易所的策略都加进「待处理」
  （`build_strategy_record_payload` 的 `exchange_snapshot.get("error")` 分支），
  列表却不会同步多出这些卡——数字和列表对不上。

### 2.5 卡片重叠的原因（本地最小复现已确认）

首页里这个列表放在一个定高的容器中（`.workbench-panel[data-workbench-panel="strategies"]`
`height:100%`，列表行 `minmax(0,1fr)`），卡片列表 `.home-event-feed` 是 CSS Grid。
卡片 `.home-event-card` 带 `overflow: hidden`，按 Grid 规则，这种元素的「最小高度」
不再按内容算，而是按 `min-height: 44px` 算；容器又是定高，于是**每一行被压到 44px**，
桌面两栏布局 `align-items: start` 让卡片按内容高度画出来，溢出本行、被下一行的卡片盖住。

复现页实测：修复前 `grid-template-rows` = `44px ×7`；给列表加
`grid-auto-rows: max-content; align-content: start;` 后每行 166px、列表正常滚动、无重叠。

### 2.6 和其他页面的分工

| 页面 | 回答的问题 | 和「策略」页的重叠 |
|---|---|---|
| 持仓 | Deepcoin 上现在有哪些真实仓位、止损止盈在不在 | 「未归属仓位」「缺止损」两边都显示；真正能操作（平仓/补止损）的按钮在持仓页 |

页面本身从没写过这一句，副标题「每条记录都保留完整归属证据」是给开发者看的。

## 3. 方案

### 3.1 页面上写一句大白话（替换现副标题）

> 每一条被识别成交易策略的喊单都在这里，能看到它有没有真的下单、现在走到哪一步。
> 平时不用管；「需要你处理」里出现卡片时，照卡片上写的去做就行。

标题「策略记录」保留，去掉「实盘观察台」小字（它是开发阶段的名字）。

### 3.2 「待处理」改名「需要你处理」，并且只放用户**现在能做点什么**的

判定改为两步：先看这条异常**现在还有没有意义**，再看**用户能做什么**。

**一律不进「需要你处理」的**（仍在详情页的历史里保留原标签，不删数据）：

- 策略已结束（已离场 / 已过期 / 已作废 / 已取消 / 已拒绝）**并且**没有在场的真实仓位——
  不管当初是 AI 识别失败、执行失败还是止盈冲突，都已经处理不了。
- 「策略已入场但没有唯一真实仓位」发生在**只通知不交易**的群——这是设计如此，不是异常，
  直接不再当异常（卡片上改为普通状态「仅跟踪，不下单」）。

**进「需要你处理」的，每张卡写明「需要你：…」**：

| 情况 | 卡片写 | 链接 |
|---|---|---|
| 在场真实仓位缺止损 | 需要你：给这个仓位补止损，或手动平仓 | 去持仓页 |
| 交易所有仓位但对不上任何策略 | 需要你：确认这是不是你手动开的仓；不是就去持仓页处理 | 去持仓页 |
| 仓位归属冲突 / 不唯一 | 需要你：去持仓页确认这个仓位属于哪条策略 | 去持仓页 |
| 在场仓位的止盈 / 管理指令结果未确认或冲突 | 需要你：在 Deepcoin 看一下止盈止损单是否挂着，和卡片列的价位对一下 | 去持仓页 |
| 自动交易群里，策略已入场但系统没有对应仓位 | 需要你：去 Deepcoin 看是否真有这个仓位；没有就不用管，系统会在策略过期后自动收掉 | 去持仓页 |
| 仍在等入场的策略（待入场）AI 识别失败 / 存在关键分歧 | 需要你：看一眼原消息，判断要不要手动跟；系统不会替你下单 | 详情页 |
| 仍在等入场的策略执行失败（下单被拒） | 需要你：看失败原因；多数不用管，想跟就手动下 | 详情页 |

另外：Deepcoin 快照读不到时，**不再**把所有策略算进来，改为顶部一条横幅
「Deepcoin 暂时连不上，仓位相关检查暂停」，计数不虚增。

「需要你处理」为空时显示：「现在没有需要你处理的事。」

### 3.3 历史记录怎么排除：三个选项（请拍板，见第 4 节 Q1）

- **A. 状态规则（推荐）**：按 3.2 的规则——策略已结束且没有在场仓位 → 不进。
  不需要时间参数，今天的 203 条会全部退出，以后也不会再积累。
- **B. 时间窗**：只看最近 N 天（比如 3 天）内有变化的。简单，但会把「3 天前开的、至今缺止损的仓位」也藏掉，
  和「缺止损要一直提醒」矛盾。
- **C. A + 时间窗兜底**：A 为主；另外「待入场策略的 AI 识别问题」超过 24 小时自动退出
  （待入场策略本来就会过期，这只是让它早点安静）。

### 3.4 「标记已知悉 / 归档」按钮（请拍板，见 Q2）

按 3.3-A 做完，今天的待处理会从 203 变成 0，剩下的都是「有在场仓位的问题」，
这种问题**不该**被一键归档掉（真实仓位缺止损点了已知悉也还是缺）。
而「已知悉」需要新建一张表记录谁在什么时候点过——这是表结构变更，按项目规矩要走 L3（生产库副本演练、备份）。

**推荐：这次不做**。如果之后发现某类提醒反复出现又确实不用管，再单独加。

### 3.5 按钮与计数口径统一

- 「需要你处理 N」从状态按钮那一排里拿出来，做成列表上方单独一块（有数时醒目色，零时灰色），
  明确它是「横跨所有状态的提醒」，不是一个状态分类。
- 下面一排只剩状态：**全部 = 执行中 + 待入场 + 已结束**（其他罕见状态归入「已结束」旁边的「其他」，
  没有时不显示），保证加起来等于全部。
- 所有数字和列表用**同一个判定函数**算：列表按什么条件出卡，计数就数什么条件，
  并加测试断言「每个筛选的计数 = 该筛选下能翻完的卡片总数」。
- 「执行中」对只通知的群改叫「已入场（仅跟踪）」还是维持原名，见 Q4。

### 3.6 卡片本身

- 状态标签改中文：`expired` → 已过期、`exited` → 已离场、`entered` → 已入场、`pending_entry` → 待入场、
  `not_started` → 未下单、`unbound` → 未关联仓位、`live_bound` → 有真实仓位 等（映射表放模板过滤器，未知码原样显示）。
- 时间：显示**喊单时间**（`signal_at`）为主，「最近变化」为辅，按北京时间 `MM-DD HH:mm` 显示，
  不再显示带 `+00:00` 的原始 ISO 串。
- 「需关注：AI识别失败 ›」这一行，在「需要你处理」卡片上改成「需要你：…」；
  其余卡片的历史异常只在详情页里出现，列表卡片不再挂黄条。

### 3.7 修复卡片重叠

`static/app.css`：

```css
.strategy-record-list .home-event-feed {
  grid-template-columns: minmax(0, 1fr);
  grid-auto-rows: max-content;
  align-content: start;
}
```

只影响策略列表，不动其他用 `.home-event-feed` 的页面。加一条测试断言这条规则存在（项目没有浏览器快照测试，
用 CSS 文本断言），并在本地起预览实测桌面两栏 / 手机单栏都不重叠。

### 3.8 不改的东西

- 不改任何表结构、不写生产数据、不碰交易路径与自动交易开关。
- 不删、不改历史异常标签：详情页照旧显示完整证据。
- 持仓页不动；策略页只给出「去持仓页」链接，不在策略页加平仓 / 补止损按钮。
