# 当前持仓止盈止损历史回填方案

日期：2026-07-26  
范围：仅仍处于 `active` 的 DeepCoin 持仓；不创建、修改或撤销任何交易所订单。

## 已验证的现状

官方 DeepCoin 持仓界面按“仓位卡片”分组展示保护单，而不是在币种维度汇总。已在已登录的官方页面只读核验以下卡片：

| 官方持仓指纹 | 官方止盈止损 | 内部对应持仓 |
| --- | --- | --- |
| BTCUSDT、多、0.003 BTC、开仓均价 63,894.1 | 止损 61,000（07-25 16:45）、止盈 67,200（07-25 19:21）、止损 60,878（07-25 19:32） | `posId=1001124349284503`、当前显示 `止盈止损(0)` |

内部只读快照同时发现三笔尚未进入强证据 ledger 的交易所 TPSL：

| 交易所订单 | 类型/触发价 | 创建时间 | 当前状态 |
| --- | --- | --- | --- |
| `1001124349284502` | 止损 / 61,000 | 2026-07-25 16:45:31 | 未归属 |
| `1001124351953730` | 止盈 / 67,200 | 2026-07-25 19:21:30 | 未归属 |
| `1001124352137443` | 止损 / 60,878 | 2026-07-25 19:32:06 | 未归属 |

这解释了页面问题：展示层已经会渲染完整的 `止盈止损(n)` 列表，但只接受 `PositionProtectionLedger(order_id, pos_id)` 的精确关联；旧订单没有该关联，因此被刻意留在“未归属交易所保护单”。

## 原则

1. 回填只写本地账本，绝不向 DeepCoin 提交交易请求。
2. 自动写入只能使用交易所原始 `OrderSysID -> PositionID` 证据。
3. 官方页面的可见卡片分组可作为人工复核证据，但**不能**被程序降级为“按价格、数量、方向、时间猜测”。
4. 每次运行先生成不可变 dry-run 清单和 SHA-256 指纹；仅在操作者确认同一指纹后写入。
5. 已有强证据 ledger 不覆盖；冲突、缺字段、持仓已平或订单不再挂起的记录一律跳过并报告。

## 分两阶段实施

### 阶段 A：采集与 dry-run（只读）

1. 从当前持仓接口取得活跃仓位及原始 `PositionID`。
2. 从当前 TPSL 委托接口取得原始 `OrderSysID`、触发类型、价格、数量、创建时间。
3. 优先读取官方前端调用中已返回的 `OrderSysID` 与 `PositionID` 对；将原始响应脱敏后保存为一次性审计证据，不保存会话、Cookie 或密钥。
4. 生成三类结果：
   - `exact`: 原始字段给出唯一 `order_id -> pos_id`，可候选回填；
   - `review`: 官方 UI 卡片已人工核验，但尚未获得原始字段；只打印候选，禁止自动写入；
   - `skip`: 冲突、无关联或非当前持仓。
5. dry-run 输出每笔的订单 ID、目标 pos ID、来源、证据哈希、预期页面变化；例如本次已人工核验的卡片预期从 `止盈止损(0)` 变为 `止盈止损(3)`。

### 阶段 B：受控写入与复核

1. 命令必须带 `--apply --manifest-sha256 <dry-run 指纹>`；没有二次确认只运行 dry-run。
2. 对 `exact` 项写入幂等的 `PositionProtectionLedger`：`venue`、`exchange_order_id`、`pos_id`、类型、价格、数量、采集时间、`evidence_source=official_api_exact`、原始证据哈希。
3. `review` 项不自动落库。若操作者针对清单逐条确认，可用单独 `--approve-order <id> --target-pos <id>` 写入，并标注 `evidence_source=official_ui_supervised`、卡片指纹、截图/快照哈希与操作者确认时间。
4. 事务提交后重新读取交易所当前持仓和 TPSL，且重新渲染内部 `/positions-panel`；只有订单仍存在、目标仓位仍活跃、渲染数量与回填清单一致时才标记完成。
5. 失败时不删除现有 ledger；输出可重试清单。重复执行必须零新增、零覆盖。

## 本次执行建议

先实现并运行阶段 A。当前已观察到的三笔记录应先进入 `review` 清单；若能从官方接口取得同一批记录的原始 `PositionID`，它们才会升级为 `exact` 并可批量回填。这样既能修复当前持仓展示，也不会把历史相似止盈止损错误绑定到另一笔仓位。
