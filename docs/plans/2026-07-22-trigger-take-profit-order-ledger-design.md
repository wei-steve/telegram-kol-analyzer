# 触发腿分段止盈与委托历史台账设计

## 目标

当 DeepCoin 触发限价入场成交后，为该精确持仓腿收敛为策略定义的分段止盈。每个止盈委托的创建、撤销、成交或失效均保留永久审计记录，并能在策略详情和告警中按持仓腿查看。

当前实盘仓位不属于本次代码发布的自动修复范围；任何历史腿的交易所变更仍需单独确认。

## 方案比较

1. 独立止盈委托台账（采用）：以策略腿和 `posId` 为边界，保存交易所委托及完整状态迁移。它能可靠表达多档 TP、多次替换和撤销过程。
2. 扩展已有保护台账：改动较小，但现有语义主要是“当前归属的保护”，不适合保留撤销和重建链路。
3. 仅展示交易所快照：无法证明历史归属，也无法审计系统是否曾发起撤销。

## 数据模型

新增 `trigger_take_profit_convergences`：每个触发入场腿至多一条，保存不可变的目标价格/比例计划，并记录从等待精确仓位到执行完成或冻结的状态。

新增 `position_take_profit_orders`：每笔 TP 订单一行，字段包括：策略绑定、入场腿、`posId`、委托价格/数量、交易所订单号、状态、创建/撤销/完成时间、父收敛任务、请求/响应/错误证据。状态为 `active`、`cancel_requested`、`cancelled`、`filled`、`expired`、`submit_unknown`、`conflicted`。记录只追加状态迁移，不删除。

## 收敛流程

1. 提交触发入场前，持久化完整 TP 计划；触发单本身可保留第一档嵌入 TP。
2. 对账确认该 `ExecutionOrderLeg` 精确归属一个活动的 split `posId` 后，将收敛任务置为 `ready`。
3. 执行器读取实时仓位、待处理 TPSL、该腿台账和现有止损。仅在策略/腿/仓位唯一一致、止损存在且未漂移、TP 委托可唯一归属时执行。
4. 旧 TP 先写入 `cancel_requested` 并提交撤销；只在交易所确认后置为 `cancelled`。止损不撤销、不替换。
5. 再按实时剩余仓位及比例分配创建每档 TP，并逐笔写入 `active`。API 响应边界不明时写 `submit_unknown`，不自动重试。
6. 下一次只读对账更新订单为 `filled`、`expired` 或保持 `active`。没有明确目标的临时部分止盈导致仓位缩小，则任务置 `conflicted` 并告警，绝不猜测重分配。

## 展示与告警

策略详情按每条持仓腿显示当前 TP 列表、各订单的审计时间线和收敛任务状态。页面优先显示已核验的活动 TP；历史记录不会混入当前保护。`conflicted`、`submit_unknown`、撤销未确认和止损缺失均生成可定位到腿的告警。

## 验证

测试覆盖：10 手为 5/3/2、7 手为 3/2/2；旧 TP 的撤销/确认后才重建；止损不被取消；仓位或归属不一致、部分止盈歧义、API 结果不明均冻结且不重试；台账历史和策略详情投影完整。先运行本地单测；合并后在服务器执行真实只读核验。实盘历史腿修复须另行确认。
