# 第一止盈成交后自动成本保护设计

## 目标

当一个自动交易策略的任意精确持仓腿被交易所证明已经完成第一档止盈，或者群组明确要求部分离场且部分平仓已经成交时，系统自动撤销该策略剩余未成交入场腿，并把该策略全部实时持仓腿的止损收紧到各自交易所实际持仓均价。若行情已经反穿成本价，导致成本止损不再合法，则市价退出对应持仓腿。

本设计不改变现有首次策略识别、上下文策略指向或仓位归属规则。自动成本保护只能消费这些权威结果，不能替代、绕过或复制它们。

## 已确认问题

系统已有 `move_stop_to_breakeven_after_tp1` 设置，默认值为开启，页面也允许配置，但该设置尚未接入真实 Deepcoin 第一止盈成交与仓位保护执行链路。

当前存在两条互不完整的路径：

- `StrategyLifecycle.filled_tp_index` 可以通过行情 K 线推进生命周期统计，但不会修改真实交易所持仓。
- 消息驱动的 `partial_take_profit` 只有在消息同时明确包含保护成本语义时才会进入 `partial_then_break_even`；仅有部分止盈指令不会自动保护剩余仓位。

大镖客 `#4163` 暴露了两个直接后果：第一档止盈确实把 10 张空单减为 5 张，但本地止盈订单状态没有可靠收敛到成交；后续成本保护消息因多策略目标不唯一而被安全跳过。剩余空单继续使用原始止损，行情反转后形成浮亏。

## 已批准策略

### 触发证据

只接受交易所实际成交证据，不接受价格触碰作为触发条件。

触发来源有两类：

1. 已归属的第一档止盈订单被交易所证明成交。
2. 群组明确要求部分止盈、减仓或只留尾仓，并且现有管理批次已经证明部分平仓成交。

新开反向策略不自动证明旧策略结束。交易者可能有意同时持有多空，因此反向开仓只能作为人工检查提示，不能授权平仓、撤单或修改止损。

### 未成交入场腿

任一持仓腿确认第一止盈后，先撤销该策略全部未成交入场腿和补仓腿，再修改已持仓腿保护。撤单未被交易所回读确认为终态时，后续保护写入和全平写入全部停止。

### 成本保护价格

每条实时持仓腿独立使用 Deepcoin 当前仓位快照中的实际均价 `avgPx`。不使用策略建议入场价、入场区间中点或另一条持仓腿的均价。

如果现有止损已经比 `avgPx` 更有利，则保留现有止损，不向风险方向放宽：

- 多单只允许提高止损；
- 空单只允许降低止损。

### 多持仓腿联动

同一策略任意一条精确持仓腿确认第一止盈后，保护该策略当前全部已验证实时持仓腿。每条腿使用自己的 `posId`、`avgPx`、数量和保护订单集合。

## 方案比较

### 方案一：只增强消息识别

把“第一止盈、部分止盈、减仓”等消息统一识别成部分平仓加成本保护。实现范围小，但交易者不发消息、只做事后回顾或消息目标不明确时仍会漏掉保护。

### 方案二：行情触价驱动

当行情触及第一止盈价时直接调整止损。响应最快，但价格触碰不等于交易所订单成交，可能在订单未建立、数量不足、滑点或交易所状态未知时错误修改仓位。

### 方案三：交易所成交收敛并复用现有管理边界

由只读交易所对账证明第一止盈成交，创建持久化的策略级自动成本保护任务，再复用现有精确归属、撤销入场腿、市场判断、仓位写入和回读边界。消息驱动的部分平仓在成交确认后进入同一收敛流程。

采用方案三。它覆盖无消息场景，同时保留现有 fail-closed 安全边界。

## 架构

新增一个策略级自动成本保护收敛器，而不是新的策略解析器。

```text
Deepcoin 只读快照 / 已完成的部分平仓管理批次
  → 第一止盈成交证据判定
  → 持久化自动成本保护任务
  → 冻结策略级目标快照
  → 撤销全部未成交入场腿
  → 回读撤单终态
  → 重新读取全部 verified 实时持仓腿
  → 为每条腿作成本保护市场判断
      ├─ 成本止损合法：收紧到 avgPx
      ├─ 现有止损更优：保持不变
      └─ 行情已反穿成本：精确 posId 市价全平
  → 回读仓位和保护订单
  → completed / recovery_required / blocked
```

现有 `strategy_management_market_policy` 和持久化市场决策负责判断成本止损是否合法。多单要求市场价严格高于成本价，空单要求市场价严格低于成本价；否则使用既有 `full_exit` 回退语义。

## 持久化模型

新增 `strategy_break_even_convergences` 表，保存一次不可变、可恢复的策略级任务。建议字段包括：

- `id`；
- `venue`；
- `strategy_instance_id`；
- `execution_binding_id`；
- `target_lifecycle_id`；
- `trigger_type`：`tp1_fill` 或 `confirmed_partial_close`；
- `trigger_order_id` 或 `management_batch_id`；
- `trigger_evidence_json`；
- `target_snapshot_json`；
- `status`；
- `reason_code`；
- `planned_at`、`started_at`、`completed_at`、`updated_at`。

幂等键为：

```text
venue + strategy_instance_id + trigger_type + trigger_identity
```

其中 `trigger_identity` 是第一止盈精确订单 ID，或已经确认部分成交的管理批次 ID。同一成交证据在服务重启、重复对账或消息重放后只能恢复原任务。

每条目标持仓腿的进度写入子表 `strategy_break_even_convergence_legs`，至少记录：

- `execution_order_leg_id`；
- `pos_id`；
- 计划时数量和实际均价；
- 原保护快照；
- 决策：`set_break_even`、`keep_tighter_stop` 或 `full_exit`；
- mutation intent、exchange order ID 和回读结果；
- 独立状态与错误。

所有真实写入继续通过 `PositionMutationIntent` 和 `ExecutionEvent` 记录，不允许收敛器直接调用无审计的交易所写接口。

## 第一止盈成交证明

### 一级证据

优先接受：

- `PositionTakeProfitOrder` 或 `PositionProtectionLeg` 已精确绑定第一档止盈 `ordId`；
- Deepcoin 成交、订单历史或触发订单历史返回相同 `ordId` 的成功终态；
- 订单的 `posId`、方向和数量与本地不可变账本一致。

### 二级结构化证据

Deepcoin 某些原生仓位 TPSL 不稳定地出现在历史接口中。只有以下事实全部同时成立时，才允许以交易所状态迁移证明成交：

- 第一档止盈此前已经通过待执行接口回读验证；
- 第一档止盈精确 `ordId` 从完整待执行快照消失；
- 同一精确 `posId` 仍存在；
- 当前仓位数量相对最后一次完整快照恰好减少第一档止盈数量；
- 其余已归属止盈订单仍与预期一致；
- 没有同一时间窗内的人工平仓、消息减仓、未知写入结果或其他可解释数量变化的 mutation intent；
- 交易所快照完整，不存在分页、接口错误或归属冲突。

结构化证据仍是交易所实际仓位与订单状态确认，不是行情触价推断。任一条件缺失时任务不得创建，并生成高优先级人工复核事件。

为支持数量差异证明，对账器必须持久化每个精确 `posId` 最近一次完整仓位数量、对应保护订单集合、快照时间和摘要。不能用进程内缓存作为授权证据。

## 消息驱动的部分离场

权威识别和上下文目标解析保持不变。只有已经唯一绑定现有策略、并成功生成管理批次的明确减风险消息才进入执行。

当 `move_stop_to_breakeven_after_tp1` 开启时：

- `partial_take_profit`、明确减仓和只留尾仓统一采用“部分平仓成交后成本保护”的策略；
- 部分平仓请求尚未确认、部分成交数量不明确或交易所结果未知时，不修改止损；
- 部分平仓确认后，以管理批次 ID 创建或采用自动成本保护任务；
- 由自动成本保护任务处理策略级撤单和全部实时持仓腿保护。

这样可以避免消息执行器与交易所成交对账分别实现两套成本保护逻辑。

## 执行边界

任务执行顺序固定如下：

1. 验证开关仍开启，任务证据和幂等身份完整。
2. 验证 lifecycle、binding、entry leg 和 `posId` 归属仍然精确且无冲突。
3. 冻结当前全部未成交入场腿、实时持仓腿、数量、均价和保护订单。
4. 精确撤销快照中的未成交入场腿。
5. 回读确认每条入场腿已终态；若撤单期间成交，把新 `posId` 纳入同一策略目标后重新规划。
6. 重新读取一次完整 Deepcoin 仓位、订单、TPSL 和最新行情。
7. 对每条实时持仓腿作不可变市场决策。
8. 现有止损更优时不写交易所，仅记录 `keep_tighter_stop`。
9. 成本止损合法时，取消并替换该腿止损，同时保留按当前剩余数量合法化后的未成交止盈计划。
10. 成本止损不合法时，使用精确 `closePosId` 市价全平该腿。
11. 回读每条腿的仓位和保护订单，写入精确账本。
12. 全部目标达到终态后完成任务；单腿失败不会重复执行其他已成功腿。

保护替换必须复用现有止盈数量消费和验证逻辑，确保已成交第一档不会被重新创建，剩余止盈数量总和不超过当前仓位。

## 状态机

```text
planned
  → preflight_verified
  → cancelling_deferred_entries
  → deciding_by_market
  → executing
  → reconciling
  → completed
```

异常状态：

- `blocked`：写入前证据不足或开关关闭，零交易所写入；
- `recovery_required`：请求可能已经发送但结果未知，只允许回读；
- `failed_terminal`：交易所明确拒绝、目标身份失效或任务证据损坏，需要人工处理。

## 开关语义

`move_stop_to_breakeven_after_tp1` 成为真实执行开关：

- 关闭：仍对账并记录第一止盈成交证据，但不创建交易所写任务；
- shadow：创建完整任务和决策，不撤单、不改止损、不平仓；
- live：按本设计执行。

执行模式复用现有 `management_execution_mode`。全局自动交易关闭时不允许新建 live 写任务，但已产生未知交易所结果的任务仍必须继续只读恢复。

## 告警和可观测性

每个任务展示：

- 触发来源和精确证据；
- 第一止盈订单、原数量和剩余数量；
- 被撤销的入场腿；
- 每个 `posId` 的 `avgPx`、市场价和最终决策；
- 原止损、新止损或全平订单；
- 回读状态和失败原因。

以下情况发送高优先级系统操作员告警：

- 第一止盈订单消失但数量变化无法唯一解释；
- 未成交入场腿撤销结果未知；
- 目标策略出现未归属或冲突持仓；
- 成本保护或全平请求结果未知；
- 任务超过执行时限仍未完成。

告警投递失败不能授权重复交易。

## 测试

至少覆盖：

- 单腿 `10 → TP1 成交 5 → 剩余 5`，止损移动到该腿 `avgPx`；
- 两条实时持仓腿中一条 TP1 成交，两条都按各自 `avgPx` 保护；
- 一条实时腿和一条未成交补仓腿，先撤补仓腿再保护；
- 撤补仓腿期间发生并发成交，新腿被重新纳入计划；
- 明确部分止盈消息只有在部分平仓确认后才触发成本保护；
- 一级精确 `ordId` 成交证据；
- 二级订单消失加精确数量减少证据；
- 订单消失但数量未减少、减少量不符或存在人工减仓时零写入；
- 当前价格仍在成本价有利侧时设置成本止损；
- 当前价格已经反穿成本价时精确全平；
- 现有止损优于成本价时保持原止损；
- 已成交第一档不会在保护重建时复活；
- 开关关闭和 shadow 模式零交易所写入；
- 服务重启、重复快照、重复消息和并发 worker 零重复撤单、改止损或平仓；
- 单腿未知结果只回读，不影响其他已完成腿；
- 新开反向策略不自动关闭旧策略。

## 发布和回滚

1. 本地完成 schema、纯证据判定、任务规划和执行器测试。
2. 先部署 dormant/shadow，保留当前生产路径。
3. 回放大镖客 `#4163`：预期识别第一档 5 张已成交、撤销 17 张未成交补仓腿，并为剩余 5 张生成成本保护决策；禁止发送真实写请求。
4. 对近期多腿、部分止盈、人工减仓和反向策略样本做只读回放。
5. 只有在任务证据零歧义、无活跃时间敏感操作且回滚路径验证后才能启用 live。
6. live 后逐任务回读 Deepcoin，确认无重复订单和止盈数量复活。

回滚时关闭 `move_stop_to_breakeven_after_tp1` 或将管理执行模式切回 shadow，并回退代码。保留任务、mutation intent、execution event 和交易所证据，禁止删除审计记录或重放已确认写入。

## 验收标准

- 第一止盈实际成交后，不依赖后续群消息即可保护剩余仓位。
- 任意一条腿触发后，策略全部实时持仓腿按各自实际均价处理。
- 所有未成交入场腿在保护写入前已撤销并回读。
- 行情已经反穿成本价时不会留下浮亏尾仓。
- 已经更优的止损不会被放宽。
- 已成交第一档止盈不会被重新创建。
- 只有精确交易所成交证据能触发，价格触碰和反向开仓均不能触发。
- 重启、重复对账和重复消息产生零重复交易。
