**对 §8 问题 1 的含义：**
- 用户的意见有两半。
  - 前一半是「需要结合上下文才能判断」。它**不支持**原来的乙案，也就是靠 `hold + unknown` 不触发来省调用。这类消息不是可以跳过复核的无害消息，而是需要上下文才能判断的消息。
  - 后一半是「预告不能下单」。它要求**无论上下文怎么判，这类消息都不能落到交易所**。
- 所以阶段 3 的设计从「要不要触发上下文」改成两件事：
  1. **识别层**：管理元素需要一个「可执行性」判据，即是否带具体价位或明确动作（止盈 X% / 平 / 撤 / 设止损 P）。不满足的判为意向，不进管理链路的执行分支；要不要为它调上下文，只影响记录，不影响交易。
  2. **执行层**：加一道确定性闸门，管理动作没有具体价位也没有明确动作动词时，拒绝写交易所。这条与模型怎么分类无关，可以单独测试。
- 这是阶段 3 的**设计变更**，要改契约和提示词，须在阶段 3 设计时写进设计稿，并由用户确认。
  现有执行链路里是否已有等价的闸门（例如「继续持有」今天会不会被执行），阶段 3 设计时要先核实，本次没有查。
