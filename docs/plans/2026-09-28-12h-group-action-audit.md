## 3. 错误与可疑项

### E1（错误，严重）陈哥 #19598 保本移止损被别的群的挂单拦住，拖了一小时

- 13:44 「比特币目前浮盈 700 点左右，上移止损 83000 附近做好成本保护」。
- 识别、上下文、目标都对：lifecycle 1348 → binding 387，两张仓位 1001125406857038 / …7169，
  保本参考价 83150（策略中点，显式价 83000 按规则让位给策略价，incident 2416）。
- 执行在预检立刻失败：`protection_rows_unattributed_on_exchange:1001125406857038:1001125407523144,1001125407523252`。
  这两个订单号是**大漂亮 binding 388 两条限价入场腿自带的止损**（当时都还没成交，账本里还没有它们）。
- 根因：`protection_attribution.match_position_protection` 里的 `unowned_order_present` 是**全账户
  一个布尔值**——只要交易所上有任何一张账本认不出的 TPSL 单，**所有**仓位的保护都会被判成
  `present_but_ambiguous`（`global_unowned_order_present`），于是 `strategy_management_executor`
  拒绝任何需要改止损的管理动作。限价入场腿自带的止损在成交前本来就不在账本里，所以
  **只要任何一个群挂着带止损的限价入场单，其他所有仓位的「移止损 / 保本」都会被拒**。
- 后续：批次 184 停在 `blocked`，值守 case 32 13:45 提出 `adjust_stop_loss` 提示，14:15 无人批准过期；
  14:45 批次超时（incident 2419）。同一分钟 KOL 发 #19636「触发成本保护」，系统市价平仓。
- 实际结果：两张仓位 82915.9 平，−3.31 USDT。若 13:44 止损已移到 83150，约 −0.97 USDT。**多亏约 2.3 USDT**。
- 值守 incident 2417/2418（执行结果未知）、2419（恢复超时）已送达。

### E2（错误，严重）米娅 #19597「减 50% 仓位，剩余止损上移至 83200」被误判成减仓比例无效

  `message_recognition._authoritative_current_message_text` 把**原文与模型的 observed_text 拼在一起**

  observed_text 里的「减50」，把「剩余」绑到这个「%」上，取到的值是「83200！…减50」，判为格式无效。
  **只用原文校验是通过的**。这是拼接文本造成的误拒，不是 KOL 措辞问题。
