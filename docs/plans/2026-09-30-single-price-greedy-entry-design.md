## 1. 现状（只读核实）

### 1.1 下单草稿在哪里决定

所有新开仓草稿最终都由 `deepcoin_order_builder.build_deepcoin_order_draft()` 生成；
调用方是 `auto_trade_execution.py` 里的三条分支（约 1360–1410 行）：

| 分支 | 触发条件 | 草稿函数 | execution_plan 标签 |
| --- | --- | --- | --- |
| 多片段拼装 | 有 entry_allocations / supplemental 价 / 拼装片段 | `_build_auto_adjacent_deepcoin_draft` | `adjacent_multi_fragment_entry` |
| 纯市价 | 文本含「市价/现价/直接/马上/立即/market」，或单一价 +「附近/左右/一线」且现价偏离 ≤ 0.15 % | `_build_auto_market_deepcoin_draft` | `single_entry_market` |
| 贴边混合 | 限价单，且现价离「贪婪边」≤ `market_leg_threshold` | `_build_auto_hybrid_deepcoin_draft` | `range_hybrid_market_half_limit_half` |
| 其余 | 上面都不满足 | `enqueue_recovery_trade_signal` → 同一个 builder | 无标签 |

### 1.2 区间价：两条腿怎么算（`deepcoin_order_builder.py`）

以做多、区间 `low–high` 为例（做空镜像）：

- 贪婪边 anchor = `high`（做空为 `low`）。
- **现价离 anchor ≤ `market_leg_threshold`**（`_hybrid_market_entry_price`，绝对值，两侧都算）：
  - 贪婪腿 = **市价**，价格记为现价；
  - 保守腿 = 限价 `low + second_limit_offset`。
- **离得远**：两条都是限价（`_range_entry_leg_prices`）：
  - 贪婪腿 = `high + first_limit_offset`（比 KOL 上沿再让一点，更容易成交）；
  - 保守腿 = `low + second_limit_offset`。
- 仓位分配 `_range_entry_allocations`：按两腿到止损的距离比例给贪婪腿 50 %–65 %，其余给保守腿。
- 数量按风险定额：每腿 `qty = 风险预算 × 分配% ÷ |腿价 − 止损|`。
- 生产阈值（`trading_settings.symbol_entry_thresholds`）：

  | 币 | market_leg_threshold | first_limit_offset | second_limit_offset | 阈值约占币价 |
  | --- | --- | --- | --- | --- |
  | BTC | 200 | 90 | 90 | ≈ 0.24 % |
  | ETH | 4 | 2 | 2 | ≈ 0.15 % |
  | SOL | 0.3 | 0.1 | 0.1 | — |

  `allowed_symbols` = BTC / ETH / SOL，三者都配了阈值，所以「没配阈值的币」目前在生产里不会发生。

### 1.3 单一价：为什么是「保守」

`build_deepcoin_order_draft` 第 83 行 `single_entry_price = math.isclose(low, high)`，然后：

1. `hybrid_market_price` 只在 `not single_entry_price` 时计算 —— **单一价永远不会走市价腿**；
2. 落到 `elif order_type == "market" or single_entry_price:` 分支，生成**一条 100 % 仓位的限价单，价格就是 KOL 的价**，
   不加 `first_limit_offset`。

所以单一价 = 整单挂在 KOL 价位等。现价已经越过入场价（做多时现价 < 入场价）时，
这张限价买单是「可立即成交」的，会按市价附近成交，实际效果等于市价；只有现价还没到入场价时才会挂着等。

两个附带发现：

- 单一价 + 现价贴近时，调用方会走「贴边混合」分支、贴上 `range_hybrid_market_half_limit_half` 标签，
  但 builder 里被 `single_entry_price` 挡住，**实际仍是一条限价单**。30 天里有 7 单是这种「标签说混合、实际是限价」。
- `trading_settings` 里的 `entry_range_order_style = "eager"` 和 `max_market_entry_deviation_pct = 0.15`
  在执行代码里没有任何读取点（死设置）。本方案不动它们，只记录。
- 未成交的入场限价**没有自动过期**：一直挂到 KOL 发撤单 / 管理指令，或人工处理。

### 1.4 其他相关机制与本方案的关系

| 机制 | 关系 |
| --- | --- |
| 「附近/左右/一线」+ 偏离 ≤ 0.15 % 转市价（`nearby_entry_market_deviation_pct`） | 保留，先判；贪婪规则是它的超集（不要求出现「附近」字样） |
| 纯市价入场有止损即可、3 分钟时效（D，72313b0e，`PURE_MARKET_ENTRY_MAX_AGE`） | 复用同一个 3 分钟时效：消息超过 3 分钟才进入下单（被准入屏障延后、恢复重放等），**不转市价**，退回原来的限价 |
| 半仓入场 / entry_context 定量（`effective_risk_multiplier`、拼装的 risk budget） | 不受影响：风险预算在草稿之前已定，贪婪只改「在哪个价、用什么单型」，数量仍按 `风险预算 ÷ |成交价 − 止损|` |
| 准入屏障（`assess_entry_assembly_admission`、WS 观察、未保护持仓、群持仓上限） | 全部在草稿之前，不变 |
| 几何检查 `validate_candidate_entry_price_geometry` | 仍按 KOL 入场价校验；**新增**：转市价时再用现价校验「止损 < 现价 < 第一止盈」（做空镜像），不满足就退回限价 |
| 止损必填 | 不变；市价单同样随单带止损（与现有 `single_entry_market` 相同的 payload） |
| 改价（entry_revision） | **不在本期范围**：改价仍按现有逻辑重挂 |

### 2.2 回放方法

- 行情：Binance USDT 永续 1 分钟 K 线（Deepcoin 公共 K 线不便分页；两者 BTC 差价约 1 USD，量级可忽略）。
- 样本：BTC/ETH 单一价、止损与止盈都能解析、止损距离 < 15 % 的 109 条（其中文本本身就是市价的 50 条，两种规则下都一样）。
- 下单时刻 = 消息后 1 分钟的开盘价 P0。
- 限价「错过」= 24 小时内先碰到第一止盈、或 24 小时都没碰到入场价。
- 成交后结局：先碰止损记 −1R，先碰第一止盈记 +xR，同一根 K 线两者都碰按止损算（保守）；7 天未了按收盘价计。
- R 按风险定额计算，所以止损结局恒为 −1R，贪婪的代价体现在赢单的 R 变小。
- 简化：不模拟分批止盈、保本、KOL 中途管理指令；所以绝对 R 值只能横向比较，不能当真实盈亏。

## 3. 方案

### 3.1 「单一价按贪婪腿」的精确定义

把单一价 `E` 看成 `low = high = E` 的区间，**只保留贪婪腿，整单 100 % 走这一条腿**：

记 `P0` = 下单前读取的 Deepcoin 现价，`thr` / `off` = 该币的 `market_leg_threshold` / `first_limit_offset`。

| 情形（以做多为例，做空镜像） | 新行为 | 现行行为 |
| --- | --- | --- |
| A. `|P0 − E| ≤ thr`（贴近，含小幅越过） | **市价**，整单，数量按 `风险 ÷ |P0 − 止损|` | 限价挂 E |
| B. `P0 > E + thr`（还没到，离得远） | **限价挂 `E + off`**（与区间贪婪腿 `high + first_limit_offset` 一致） | 限价挂 E |
| C. `P0 < E − thr`（已越过入场价，朝止损方向走得更深） | 限价挂 `E + off`，可立即成交 → 实际按市价附近成交（与现行一样）；若 `P0` 已到/越过止损 → 按现有几何规则拒绝 | 同左（限价挂 E，立即成交） |
| D. 已越过入场价、且朝止盈方向（做多 `P0 > E`）——即情形 A/B 的「不利偏离」 | 距离 ≤ thr 走 A，> thr 走 B | 限价挂 E |
| E. 转市价时 `P0` 不在「止损 < P0 < 第一止盈」之间 | 不转市价，退回现行限价 E | — |
| F. 消息年龄 > 3 分钟（被准入屏障延后、恢复重放、reconcile 补回） | 不转市价，退回现行限价 E | — |
| G. 现价读不到 | 退回现行限价 E | — |

说明：

- 做空时「朝止盈方向越过」= `P0 < E`；「朝止损方向越过」= `P0 > E`。上表的方向词对做空自动镜像。
- 情形 C 不变更：限价已经可立即成交，现状就是「贪婪」的；数量按 E 计算，实际风险略小于预算，保持现状。
- 「附近」规则（0.15 %）先判，命中则仍走原 `single_entry_market`。

### 3.2 时效

- 转市价只在消息年龄 ≤ 3 分钟时发生（复用 `PURE_MARKET_ENTRY_MAX_AGE`）。
- 挂出去的限价单仍**没有自动过期**（与现状一致）。给未成交单加过期是独立话题，本期不做（见 Q5）。

### 3.3 仓位

整单 100 % 走贪婪腿，不再保留挂在 E 的部分（回放显示单一价下拆腿几乎没有差别：两腿价差只有 `off`）。

### 3.4 没配阈值的币

`thr = 0` 时 `_hybrid_market_entry_price` 返回 None、`off = 0`，结果就是「限价挂 E」，与现行完全一样。
目前 `allowed_symbols` 的三个币都配了阈值，所以只是兜底。

### 3.5 多片段拼装（单一价 + 补充价 / 自定义分配）

与区间的多片段一致：第一条腿按 3.1 判定（可转市价或 `E ± off`），补充价腿保持限价不变。

### 3.6 代码改动范围（草案）

1. `deepcoin_order_builder.build_deepcoin_order_draft`：新增输入 `single_price_entry_style`（`limit` / `greedy`），
   `greedy` 时对 `single_entry_price` 计算 `hybrid_market_price`（anchor = E），并把远处限价价格改为 `E ± first_limit_offset`；
   转市价时校验 `止损 < P0 < 第一止盈`，不满足退回 E 限价；新增 note `single_price_greedy_market` / `single_price_greedy_limit`。
2. `auto_trade_execution`：单一价且模式为 greedy、消息年龄 ≤ 3 分钟、现价可用时，走显式草稿分支，
   `execution_plan` = `single_price_greedy_market` 或 `single_price_greedy_limit`；
   顺手修正单一价被贴 `range_hybrid_market_half_limit_half` 标签的问题（只改标签，不改行为）。
3. `trading_settings`：新增 `single_price_entry_mode`：`limit`（默认，等于现状）/ `shadow` / `greedy`。
   - `shadow`：照现行下单，同时把「贪婪规则本来会怎样下」写进 trade_signal payload 的 `single_price_greedy_shadow`（纯计算，无交易所调用）；
   - `greedy`：按新规则下单。
   网页交易设置加一个下拉框。
4. 不改识别提示词，不改改价路径，不改数据库结构（新设置存在已有的 `trading_settings` JSON 里）。

### 3.7 测试

- builder 单测：A/B/C/E/G 各情形、做多做空镜像、thr=0、止损越界、第一止盈越界、多片段第一腿；
- auto_trade 单测：年龄 ≤/> 3 分钟、`limit`/`shadow`/`greedy` 三种模式、「附近」规则优先、标签修正；
- 真实消息回放测试：取第 2.3 节 22 条真实消息（文本、E、止损、止盈、P0）做固定用例，断言新旧两种模式的草稿（单型、价格、数量）；
- 最终候选跑一次全量 `uv run python -m pytest -q`。

## 4. 风险、部署与观察

- 级别：**L3**（交易所写入语义变化：部分原本限价的入场改为市价）。不改表结构，不做数据修复，无需快照演练。
- 回滚：设置改回 `limit` 即时生效（设置热加载），无需重新部署；代码回滚 = `tg-deploy <部署前 sha>`。
- 建议分两步：
