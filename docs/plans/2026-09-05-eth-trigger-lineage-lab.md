# ETH Trigger Lineage Lab Implementation Plan

**Goal:** 准备用户自行执行的 ETH 最小数量多空触发限价单请求，并提供独立只读 REST 采集器。

**Architecture:** 一个独立 Python 脚本提供 prepare（公开行情、规格、离线请求草案）和 observe（只读 GET、有限窗口、原始 JSONL）命令。没有交易写入函数，不接入生产 worker、不改数据库或服务。每个请求记录 UTC 开始/结束时间、原始响应正文和解析对象，不保存鉴权头。

**Tech Stack:** Python 标准库、pytest。

## 用户追加批准：由用户一条终端命令启动真实测试

用户明确要求“修改成让我粘贴到终端的命令，然后进行下单测试”，使用服务器项目凭据，ETH 最小步长、低成本。新增独立 scripts/deepcoin_trigger_lineage_live.py；原只读程序保留只读。助手只模拟测试、复制代码、校验文件；绝不执行带 --execute-eth-minimum-pair 的真实入口。

- 从身份核验通过的 worker 进程环境读取三项凭据，驻留服务器内存，不打印、不下载。已有 ETH 仓位则停止；已有挂单记录为基线，不撤销或修改。
- 实时规格计算最小量；每侧最多 0.01 ETH，名义额最多 50 USDT；最小量超限则停止，不加量。保持已确认 P±1 入场、入场价外10止损市价、cross/split，不修改杠杆。
- 仅并发提交两个 trigger-order，每侧独立 clOrdId/tag。请求落盘并 fsync 后才发出；回执原文与发送/接收时间单独持久化。没有自动重提、补单、切换字段组、改价追单或市价入场。
- 首次尝试留下独占 LIVE-ATTEMPT.json，重复粘贴同命令不会再次下单。结果未知保留 unknown，不以空查询当撤销或失败。
- 两侧接受后观察300秒；partial/unknown进行30秒有界证据查询，全部明确拒绝也取一次快照。覆盖普通活动/历史/详情、fills、仓位、触发活动/历史、自定义ID详情；触发历史最新100条的覆盖局限单独保存。
- 收尾仅针对本次 accepted 回执且不在基线中的父 ordId，当前明确 Conditional 的行调用单笔撤销。不调用 bulk cancel，不撤自动止损，不猜子单ID平仓。
- 撤销拒绝、未知或回读仍活动，标记未解决并非零退出；输出剩余ETH仓位/新挂单候选提醒用户亲自处理。5分钟观察结束不是仓位全部平掉的承诺。
- 精确撤销本次尚未触发父单是唯一自动收尾边界。无法归属的已触发子单和仓位由用户处理；未修改生产服务或数据库，无生产回滚动作。

实施：先增加失败测试，再实现并发两笔提交、持久证据、尺寸/价格门禁、去重、采集、收尾；独立代码审查后修复并运行最终focused tests。服务器只静态解析文件和核对SHA256，不启动真实入口。

## 已确认设计

- 同一 ETH-USDT-SWAP 最新成交价 P，多单触发价/委托限价 P-1，空单 P+1；多单 SL=P-11，空单 SL=P+11，SL 以 last 触发，slOrdPx=-1。
- SL 相对预设入场限价计算；限价可能获得价格改善，实际成交均价到 SL 的距离不保证恰好 10。不在成交后自动改单。
- sz=minSz 向上对齐 lotSz；数量为合约张数，ETH 名义量=sz*ctVal。价格必须精确满足 tickSz，否则停止，不静默改变已确认偏移。
- 草案使用项目常用 cross/split；执行者必须核对账户模式和杠杆，工具不修改账户设置。
- 唯一 clOrdId/tag 放入两侧请求作为待测字段；ordId 只由交易所生成。独立诊断组 baseline/clOrdId/tag 可在 prepare 显式选择，不自动追加真实订单。
- 对两侧生成同一行情基准的请求，不承诺交易所原子接收或两侧均触发。报价需标记时效。
- observe 采集普通活动/历史、触发活动/历史、fills、positions、已知 ID 详情与精确 fills；运行前开始采集，用户自行提交并保留完整提交请求/回执。
- 订单 ID 清单可在采集期间更新，下一轮读取。所有 ETH 普通列表可见 ID 均查详情，明确为候选，绝不按价格、时间相近或 ID 相邻自动建立父子关系。
- 有限采集不能证明所有生命周期事件均被看见。REST 轮询有间隙，触发历史无已确认翻页契约；页数或对象数上限、错误、缺字段均标记 unknown/incomplete。每个 GET 最多一次有界重试，第二次失败停止。
- 自动附带 SL 可见和 SL 实际触发后生成普通单是不同验收项；不主动促使真实止损成交。

## 方案取舍

采用独立只读采集器加请求文件，可隔离生产决策路径；复用原 live probe 会混入市价开平仓且无法检验本次触发链；修改生产客户端超出本次实验需要。

## 实施步骤与验证

1. 新建 tests/test_deepcoin_trigger_lineage_lab.py，验证最小张数/ETH换算、价格及止损方向、过期行情拒绝、ID 唯一性、GET 路由边界、错误不当空、分页饱和与时间记录。
2. 运行 focused tests，确认因实现缺失失败。
3. 新建 scripts/deepcoin_trigger_lineage_lab.py，实现 Decimal 草案生成、GET 白名单传输、原始证据与有限观察。
4. focused tests 通过后，只运行公开 prepare，保存当前行情和草案；不运行任何真实交易。
5. 新建操作说明，记录字段实验矩阵、观察局限、用户自行提交回执的要求、启动只读采集的方法。

范围为独立诊断工具，无生产代码、配置、schema 或部署变化。运行 focused tests、CLI 检查及真实公开 GET；不启动生产全套测试或服务。
