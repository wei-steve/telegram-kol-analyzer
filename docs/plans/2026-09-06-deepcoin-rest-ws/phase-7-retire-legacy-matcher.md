# 阶段 7：退役 `match_position_protection`

**状态：planned（只写计划，不做）。**
**前置：6b 切换完成 + 6g 切换完成。两者都未完成，所以本阶段现在不可开始。**

**编号说明**：交接文档里也提到过一个"第 7 步"（真正的条件触发策略继续用 trigger-order），
那一条**不是本阶段**——它是"保持现状"，已写进阶段 5 的禁止项，见本目录 `README.md` §5 末尾。
本阶段是另一件事：把旧的推断式保护单匹配器从生产路径上摘掉。

## 1. 要解决的问题

`protection_attribution.match_position_protection` 是改造前的匹配器：它没有绑定链，
靠**价格、数量、方向、时间距离**在挂单表里推断"哪张保护单属于哪个仓位"。
整个阶段 6 建的绑定链（`ExecutionBinding → ExecutionOrderLeg → posId → 保护单 ordId`）
就是为了取代它。

**但它今天仍在四条生产路径上**：

```
strategy_management_executor.py:666    管理批次执行
strategy_management_executor.py:3342   同上，另一处
strategy_management_planner.py:926     管理批次规划
deepcoin_execution_actions.py:82       执行动作
web_app.py:234                         （导入，需确认实际读点）
```

以及一条**影子**路径 `protection_authority_shadow.py:169`——那一条是**要留下的**：
它是新旧两条链的对照，退役之后它变成"新链 vs 已退役实现"的历史对照，
**应当随本阶段一起删掉，而不是留着一个没有对照对象的对照**。

## 2. 为什么必须等 6b 与 6g

这两个切换正是"把这四条路径改走绑定链"的那两步：

- **6b 切换**：撤销走新链。放行条件是**一次真实止损替换走通新路径并回读一致**
  （见 `phase-6a-open-verification`）。**截至 2026-09-12 未取得该样本。**
- **6g 切换**：自动管理路径改走绑定链。6g 的影子已上线并注册了自叫事故类型，
  但**管理保护替换约每四天一次**，样本未到达（登记簿 P3）。

**在它们完成之前删掉旧匹配器，等于把那四条路径变成没有实现。**
顺序是被前置关系决定的，不是偏好。

## 3. 已经攒下的证据（不是结论，是入场券）

`protection_authority_shadow` 的判定分布（全时段，截至 2026-09-11）：

```
chain_resolved_legacy_ambiguous  10
agreed                            8
chain_resolved_legacy_absent      4
set_mismatch                      2
chain_frozen                      1
```

**旧匹配器"含糊或找不到"合计 14，"一致" 8。** 另有 `break_even` 侧同向的
`legacy_would_refuse=1`（新链解得出来、旧读取器会拒）。

**这些行数不能当观测次数用**：该影子**每轮都跑**，但表是按指纹去重的
（`_record_when_changed`），**25 行是 25 次"判定发生了变化"**。
到达率要从日志行算（登记簿 P0）。

**还有一条独立的理由，与影子无关**（2026-09-11 查证）：
我们自己的历史里有 **3 个 posId 各自挂在两个不同的 strategy instance 下**，
其中 `1001123942217592` 横跨两个群、相隔一天。几乎肯定是旧匹配器把同一个活仓位
归给了两个信号。**仅凭这些行分辨不了"交易所复用 posId"与"我们误归属"**，
所以两者都不下结论——但它说明**只按 posId 或按价格推断都不足以确定"就是这一个仓位"**。

## 4. 本阶段做什么

1. **把四条生产路径逐条改走绑定链**（若 6b/6g 切换已覆盖其中若干条，则只补剩下的）；
2. **删掉 `match_position_protection` 及其唯一剩余调用方**；
3. **删掉 `protection_authority_shadow`**——对照对象没了，留着就是一个永远 `agreed`
   的空转，而空转的影子读起来和有效的影子一样；
4. **保留 `protection_attribution` 里被别处复用的纯函数**（先扫再删，不整文件删）；
5. 闸门可观测行与登记簿相应更新。

## 5. 风险等级：L3

**理由**：它改变的是"哪张保护单属于哪个仓位"这一判断的来源，
而这个判断直接决定撤单撤的是哪一张。**删掉一个回退实现，等于把新链的每一个缺陷
从"两条链不一致"降级成"无人反对"。**

## 6. 明确不做的事

- **不在本阶段修 6b/6g 的判据**。若样本仍未到达，正确的动作是继续等，
  不是把放行条件改松——本仓库已经写过"判据未达成就照实记，不悄悄放宽"。
- **不顺手删 `protection_attribution` 整个模块**。
- **不因为"旧匹配器 14 次含糊 vs 8 次一致"就认为新链已被证明**。
  那个分布证明的是**旧的不够好**，不是**新的够好**——这是两件事，
  而本仓库今天刚记过一次同形的错（零写入不证明谓词有效）。
