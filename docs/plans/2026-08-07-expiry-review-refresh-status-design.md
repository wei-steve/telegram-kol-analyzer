# 超时复核更新状态按钮设计

## 目标

把待入场策略超时复核消息中的“过期但保留挂单”按钮替换为“更新状态”。
人工点击后，系统从 Deepcoin 获取最新账户证据，沿用现有执行绑定与逐腿对账
规则更新本地状态，并在原 Telegram 消息中展示该策略每条入场腿的最新情况。

更新状态是只读复核入口，不撤单、不平仓，也不代替现有的策略识别、上下文
解析或生命周期管理流程。

## 交互设计

超时复核消息初始按钮保持三项：

- 继续等待；
- 过期并撤单；
- 更新状态。

“更新状态”使用新的 `expiry_refresh:<lifecycle_id>` 回调。点击后先回答
Telegram callback，再编辑原消息；消息正文保留原有策略上下文，并增加或替换
唯一的“最新策略状态”区域，避免重复点击不断追加内容。

状态区域至少展示：

- 当前策略生命周期状态；
- 入场进度汇总，例如“1/2 条腿已入场，1/2 条腿挂单中”；
- 每条入场腿的序号、中文状态，以及可用时的仓位 ID 或订单 ID；
- 本次成功更新时间（Asia/Shanghai）。

## 权威数据与对账

点击按钮时通过系统操作机器人现有的 `deepcoin_client_factory` 创建客户端，
复用 `reconcile_deepcoin_execution_bindings` 的完整权威对账流程。该流程综合当前
仓位、普通挂单、触发挂单、订单历史和成交记录，并按现有执行腿归属规则更新
`ExecutionBinding`、`ExecutionOrderLeg` 和相应生命周期。按钮自身不新增第二套
订单匹配或状态推导规则。

对账完成后，只查询回调中 lifecycle 对应的执行绑定与 entry legs，并生成该
策略的展示摘要。虽然权威对账会保持整个账户的本地状态一致，Telegram 消息
只展示被点击策略的结果。

## 按钮保留与收口规则

刷新后是否继续显示按钮，以该策略是否仍存在可操作的未触发入场腿为准：

- 至少一条 entry leg 仍为 `open`、`pending`、`submitted`、
  `partially_filled` 或其他现有未决状态，且生命周期仍允许超时复核：保留三个
  按钮；
- 所有入场腿均已触发并形成已归属持仓：移除全部按钮；
- 群组后续消息已经取消挂单，使生命周期进入取消、过期、离场等终态，或所有
  入场腿均已取消/终止且不再有剩余挂单：移除全部按钮；
- 部分腿已入场、其余腿已取消且没有未决腿：移除全部按钮，并在状态区域逐腿
  说明最终结果；
- 对账证据不可用、交易所查询失败或状态无法安全确定：不改变人工复核决定，
  保留三个按钮。

按钮收口不能只检查 lifecycle 总状态。已入场策略仍可能有第二条未触发入场
腿，必须同时检查对应的逐腿状态，避免过早移除操作入口。

## 失败语义

交易所读取或对账失败时采用保守行为：

- 不把旧状态伪装成本次实时结果；
- 不执行撤单、平仓或人工过期动作；
- 原消息保留策略上下文和三个按钮；
- 状态区域显示“更新失败，未改变策略或挂单状态”及非敏感错误摘要；
- 不写入成功更新时间。

Telegram 编辑失败不回滚已经完成的权威对账；错误写入日志，用户可以再次点击
按钮。重复点击必须幂等。

## 兼容性

原 `expiry_expire_keep` 命令和回调处理暂时保留，兼容已经发送但尚未处理的旧
消息；新发送的超时复核消息不再暴露该按钮。现有“继续等待”和“过期并撤单”
行为保持不变。

## 测试与验收

自动化测试覆盖：

1. 新消息第三个按钮为“更新状态”且 callback 携带 lifecycle ID；
2. 系统操作机器人只为更新状态和撤单动作创建 Deepcoin 客户端；
3. 两条腿中一条已入场、一条仍挂单时，消息展示逐腿状态并保留三个按钮；
4. 两条腿全部入场时，消息展示完成状态并移除按钮；
5. 群组消息已经取消挂单或策略已进入终态时，刷新后移除按钮；
6. 部分入场、其余取消且无未决腿时，移除按钮；
7. 交易所读取失败或证据不完整时，显示失败信息、保留按钮且不执行交易动作；
8. 重复刷新只替换单个状态区域，不重复追加；
9. 旧 `expiry_expire_keep` 回调仍可处理；
10. 原有继续等待、撤单和 callback 消息编辑测试无回归。

本地只运行不依赖生产凭据的语法和单元测试。真实 Deepcoin 对账、Telegram
按钮编辑和服务行为必须在服务器拉取 GitHub 提交、重新安装 editable package
并重启 `telegram-kol.service` 后验证；部署前确认没有正在执行的时效性策略操作。
