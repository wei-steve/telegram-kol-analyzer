# 旧第二止损交易所验证状态设计

## 问题

持仓页将 `PositionBackupStopOrder.status=active` 直接显示为“第二止损 · active”。
这些记录来自旧通用 `trigger-order` 请求；2026-07-25 的实时 DeepCoin 待挂订单与
订单历史均没有对应订单 ID，而官方 App 只显示原生 `TPSL` 主止损。因此数据库
提交记录不能作为交易所保护已生效的证据。

## 决策

持仓页以实时待挂原生 TPSL 的精确读回作为“active”的唯一依据。订单 ID、合约、
方向、触发价、数量和唯一持仓归属均匹配时才显示已生效的第二止损。

旧通用条件单记录仍保留作审计，但当其不在交易所待挂或历史中时，显示为
“交易所未验证（旧通用条件单）”，绝不显示 active。数据库对账仅更新这类记录
为 `unverified_exchange`，并记录本次读取证据；不调用任何交易所写 API。

## 约束与验收

- 不创建、撤销或修改 DeepCoin 订单；
- 原生 TPSL 已验证记录仍正常显示 active；
- 10 条历史旧记录在实时缺失时改为未验证，而非删除；
- App 显示与 Web 的有效第二止损数量一致；
- 对账命令只允许显式执行并要求读取快照指纹，避免基于过时数据写数据库。
