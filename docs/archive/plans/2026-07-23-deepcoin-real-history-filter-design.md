# DeepCoin 真实历史仓位筛选设计

## 目标

“历史仓位”页只展示 DeepCoin 已真实成交并已平仓的仓位；策略结束、未触发条件单、取消委托和过期委托不再进入该页。

## 已确认事实

- `GET /deepcoin/account/positions-history` 返回真实仓位的 `posId`、`avgPx`、`closeAvgPx`、`pnl`、`pos` 和 `closePos`。
- 已验证的真实仓位可以被本地 `ExecutionBinding.payload_json.history_metrics` 关联并完整展示。
- 缺失指标的样本为历史触发委托：`triggerTime=0`、`posId=null`、`actualPx/avgPx/pnl=null`。它们没有在交易所成交，不属于历史仓位。
- 现有 `list_exited_strategies` 将本地策略的结束状态和交易所仓位混在同一数据集，因此会把未成交记录显示为 `closed`。

## 方案比较

1. 继续显示所有结束策略，并给未成交项补标签。
   - 不能满足“页面仅真实成交历史”的定义。
2. 仅凭本地 `closed` 状态筛选。
   - 仍会保留取消或未触发的条件单，无法保证真实性。
3. 仅以 DeepCoin 已验证仓位数据作为准入条件，再关联本地策略归属（推荐）。
   - 页面数据与官方 App 语义一致；不具备真实仓位证据的记录留给历史委托页。

## 选定设计

新增一个历史仓位专用查询，只接收含有 `history_metrics` 且具备有效 `posId`、`avgPx`、`closeAvgPx`、`pos/closePos` 与 `pnl` 的绑定记录。保留现有的策略绑定信息用于展示“策略归属”，但不再用本地 `closed` 状态决定是否进入历史仓位。

页面按 DeepCoin 的最后平仓时间倒序；当同一时间相同时，以交易所仓位 ID 做稳定排序。无法证明真实成交的数据从该页剔除，而不是渲染为 `--`。

## 错误处理与验证

- 缓存缺失或字段不完整时，宁可不进入历史仓位，禁止伪造数值。
- 测试覆盖：未触发条件单被排除、完整 DeepCoin 仓位被保留、按最后平仓时间排序、页面不出现旧的“已保存下单数据回填”项。
- 在服务器上刷新服务后，调用页面接口并读取数据库快照验证每个展示记录均带 `posId` 和完整数值。
