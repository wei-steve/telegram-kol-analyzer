# 成本止损逐持仓市场决策设计

## 背景

当前 `move_stop_to_break_even` 会直接替换保护单。真实空仓
`1001124377347114` 的成本价为 `64602.9`，执行时交易所基准价为
`64688.6`，导致 Deepcoin 拒绝成本止损，系统只恢复旧止损而未完成消息动作。

同一消息可能归属多个 `posId`，且各持仓成本不同。用户已确认必须逐持仓判断：
允许的持仓挂成本止损，不允许的持仓只平掉自己，不能因为其中一腿不允许而
全平同一消息的其他持仓。

## 已批准行为

- 多仓：仅当 `成本价 < 市场价` 时允许成本止损。
- 空仓：仅当 `成本价 > 市场价` 时允许成本止损。
- 相等视为不允许。
- 每个 `posId` 独立得到 `set_break_even` 或 `full_exit`。
- 只市价平掉判定为 `full_exit` 的精确持仓。
- 若至少一腿需要平仓，取消该策略尚未成交的入场挂单，防止重新开仓。
- 市场价、持仓归属或必要保护证据不可用时，在任何交易所写入前整体阻断。

## 架构

### 不可变计划

计划器继续只负责证明消息归属、lifecycle、binding、entry leg、`posId`、持仓
数量和合约规格。成本止损批次使用新的批次级有效动作
`break_even_by_market`，不在计划阶段把整个批次预判为保护或全平，也不修改
现有幂等指纹。

计划器保存每腿成本价和精确所有权。已有保护快照可作为证据，但成本止损的
最终允许性不进入不可变目标快照，避免行情漂移迫使原地改写批次。

### 一次性执行决策

新增 `strategy_management_market_decisions` 表，每个管理批次至多一行。该行
在所有撤单、改单和平仓之前创建，包含：

- batch、strategy、instrument 和决策版本；
- 本地观测时间、ticker 数值、ticker 字段来源和交易品种；
- 按 `pos_id + execution_order_leg_id` 稳定排序的决策数组；
- 每腿成本价、方向、比较结果、`set_break_even/full_exit` 和决策指纹。

执行器在共享持仓写锁内完成：

1. 重新读取精确持仓、待成交入场挂单和待处理 TPSL；
2. 获取一次 Deepcoin ticker 原始报价；
3. 对每个精确 `posId` 应用严格方向规则；
4. 验证所有 `set_break_even` 腿拥有完整、唯一、可取消的保护单证据；
5. 在一个数据库事务中写入唯一决策行，并把各管理腿从 `planned` 保留为对应
   的决策状态；
6. 事务提交后才允许第一次交易所写入。

决策行已存在时，重启恢复只能校验并沿用原决策，不能重新按新行情改变动作，
从而避免一次消息在崩溃后得到第二种交易结果。

### 行情证据

Deepcoin client 新增结构化 ticker 读取，返回精确 `instId`、选用字段和值。
字段优先级保持与现有客户端兼容，但决策证据必须记录实际字段。现阶段使用
Deepcoin ticker 的 `last/lastPx`；若两者都不存在，则阻断，不用
`markPx/askPx/bidPx` 猜测止损基准。记录本地观测时间；一次 API 响应内找不到
唯一目标 instrument 时阻断。

### 混合执行

执行器按腿动作分流：

- `full_exit` 腿沿用现有精确数量市价平仓、durable reservation、
  `submit_unknown` 和对账逻辑；
- `set_break_even` 腿沿用现有完整 TPSL 替换与失败恢复逻辑；
- 有任一 `full_exit` 腿时，先按现有安全协议取消该策略未成交入场挂单；
- 任何腿失败只影响自己的状态，但批次汇总必须准确反映全部腿的终态。

执行顺序为先取消必要的 deferred entries，再处理 `full_exit` 腿，最后处理
`set_break_even` 腿。所有对象在第一次写入前已经完成完整预检；崩溃后仅依据
持久化 reservation 和决策恢复，不自动重提结果未知的请求。

## 授权

仅允许以下组合：

- `intent=move_stop_to_break_even`
- `effective_action=break_even_by_market`
- 存在版本正确、批次身份一致、指纹有效的唯一市场决策行

worker 直接调用 executor 时也执行同一校验，不能只依赖外层 action matcher。
普通 `full_exit`、普通止损和 `partial_then_break_even` 行为保持不变。

## 前序恢复

当前 batch 67 已恢复旧保护但账本尚需以交易所事实修复。唯一允许流程：

1. 证明旧止损已不存在、恢复止损仍待处理、精确持仓仍存在；
2. 修复保护账本；
3. 在创建新成本止损批次前，将 batch 67 终态化为 `resolved`；
4. 若新批次创建失败，事务回滚，不单独改变前序状态。

不使用当前只依赖历史 JSON 的自动 resolver 猜测恢复事实。

## 失败处理

- ticker 缺失、非正数、非有限数、字段来源不允许或 instrument 不唯一：阻断。
- 任一持仓身份、数量、方向漂移：阻断。
- 任一 `set_break_even` 腿的保护证据不完整：整体阻断，零交易所写入。
- 决策唯一键冲突：读取已有决策；指纹不匹配则进入恢复状态，禁止写入。
- 市价平仓结果未知：`submit_unknown`，绝不自动重试。
- TPSL 替换失败：恢复该腿原完整保护并记录恢复后的精确账本。

## 测试

覆盖纯方向规则、ticker 来源、单腿允许/不允许、相等边界、多腿全允许、
全不允许和混合决策、保护证据缺失时零写入、决策唯一性、崩溃恢复、精确
平仓数量、TPSL 失败恢复、deferred entry 取消，以及所有既有管理回归。
