## 结论先行

**历史上确有方向错误的保护请求到达 Deepcoin，但没有证据表明方向错误的保护单曾实际生效。**

- 全历史 1,281 条 `entry_signal` candidate 中，947 条能够用严格、可复核的绝对价格口径判断；其中 33 条方向与价格几何不一致，占全部 2.58%，占可判断样本 3.48%。另有 334 条因相对表达、缺少绝对保护价、歧义数字或非法方向而不可判断，未被当作正常。
- 33 条异常中只有 2 条能以源消息、标的、方向的严格键关联到 execution binding，且两条均实际成交：candidate 1895 与 2187。

- 两笔均没有可验证的方向错误保护单实际挂成，也没有交易所记录的已实现亏损；但系统确实曾把错误几何带到交易所写边界，且两笔成交后都出现过无有效保护的风险窗口。
- MiMo 权威 payload 与 candidate 投影在本次重点样本中一致。candidate 2187 的 payload 保留了“低接”和“分批做空”两种冲突语义，却给出 `conflicts=[]` 并选择 `side=short`；本例是识别/语义校验缺失，不是投影把方向或价格搞反。

## 2. 全历史统计

### 2.1 口径

- 母集：全历史 `signal_candidates.event_type='entry_signal'`，共 1,281 条。
- side：只接受精确的 `long` / `short`；其他值列为不可判断。
- 价格解析：沿用生产中的 symbol-aware 价格归一化能力，但只接受能够确定为绝对价格的表达；百分比、时间、倍数、空值等不被猜成价格。
- 入场参考价：一个绝对入场价取该值；两个绝对端点取中值；若文本明确给出第三个数且等于端点中值，也取该中值。其他多数字表达列为歧义，不强判。
- SL/TP：只对能够确定为绝对价格的值进行关系判断。任一已记录 SL/TP 违反下列严格不等式，即记为不一致：
  - short：`SL > entry_ref`，每档 `TP < entry_ref`；
  - long：`SL < entry_ref`，每档 `TP > entry_ref`。
- NULL、相对表达和歧义不被当成 0，也不被当成正常。

说明：生产现有宽松数字抽取器会把百分比、时间等数字也当作价格，直接复用会报出 56 条。本报告把其中 23 条无法证明为绝对价格的记录归入“不可判断”，避免把解析伪影当成真实几何错误；这处与现有解析器口径的差异已显式保留。

## 3. 模型输出与 candidate 投影

可判断的 MiMo authoritative entry candidates 中，596 条有足够绝对价格，10 条不一致，占 1.68%。这 10 条为 candidate `1180, 1225, 1300, 1318, 1578, 1895, 2114, 2136, 2177, 2187`。

- 其中 9 条的 `side / entry / stop_loss / take_profit` 与权威 payload 逐字段一致。
- candidate 1180 只有 stop 文本标点/格式归一化差异，数值与方向语义一致。
- 未发现投影阶段交换 side、SL/TP 或翻转数值关系的证据。

因此，本次已核查的 MiMo 异常属于模型输出本身或权威输出进入 candidate 前缺少语义一致性验证，不属于 candidate 投影反向。

### candidate 2187

权威 payload 记录：

- `recognition_result=是策略`、`event_type=entry_signal`、`side=short`；
- entry=`79500-76500区域附近分批做空，均价78000附近`；
- stop_loss=`76000`；take_profit=`81500-83000-85000`；
- evidence 中保留了“趋势有反转迹象，突破后表现强势，回调可以观察低接”和“分批做空”两类冲突文本；
- 但 `evidence.conflicts=[]`，reason 只称参数完整，没有解释或解决多空语义矛盾。

可确认模型直接采用了“分批做空”的字面动作词，同时没有把“低接”及 SL/TP 几何只支持 long 这一冲突上报。现有数据不能证明模型内部推理过程，不能进一步声称它为何选择 short。
